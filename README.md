# 知余

个人债务管理应用。当前交付包含 React Web、Rust/Axum API、SQLite 本地存储与 Turso 远程连接能力。首版 UI 仅使用人民币，金额在 API 与数据库中统一保存为整数分。

## 环境要求

- Rust `1.93.1`（由 `rust-toolchain.toml` 固定）
- Node.js 22+
- pnpm `10.12.1`

## 本地开发

```bash
cp .env.example .env
pnpm install --frozen-lockfile
pnpm dev
```

- Web: <http://127.0.0.1:5173>
- API readiness: <http://127.0.0.1:8790/health/ready>
- OpenAPI: <http://127.0.0.1:8790/api/openapi.json>
- 开发验证邮件：`var/dev-mail/`

`pnpm dev` 使用 `file:./var/preview.db` 保留本地演示账本；如需空白账本或自定义数据库，可直接设置 `DATABASE_URL` 后启动 API。构建 Web 后，Axum 会同源托管 `apps/web/dist` 并为 SPA 深链接返回入口文件。

## 债务金额语义

- 一笔债务的方向创建后不可改变：借入债务只能继续“追加借入”，借出债务只能继续“追加借出”；反方向往来应新建另一笔债务。
- `累计本金 = 初始本金 + 追加金额`，`净已还 = 还款金额 - 已撤销还款金额`，`剩余金额 = 累计本金 - 净已还`。追加不会改变已还金额，提交后会立即等额增加累计本金与剩余金额；追加日期只用于往来留痕。
- 已结清债务可以追加并重新进入进行中、临近到期或已逾期状态；已归档债务不能追加，需先恢复。
- 追加记录和未撤销的原还款记录可在往来记录中编辑金额、日期、账户和备注；系统会在同一事务内重算本金、已还和剩余金额。编辑追加不能使本金低于已还，编辑还款不能超出剩余金额。
- 撤销还款是不可编辑的补偿记录，已撤销的原还款及归档债务的往来记录也不可编辑。已有追加或还款历史后，本金不能直接修改，债务也不能直接删除，只能归档。

## 资金账户与溯源

- 先在左侧“账户管理”中选择固定账户类型。账户名称是用于区分同类账户的可选别名；银行卡可填写银行卡号、银行和开户行，未填写别名时按“银行卡号 → 银行 → 开户行”派生名称；微信零钱与支付宝分别按“昵称 → 手机号”“昵称 → 手机号 → 邮箱”派生。现金、数字人民币和其他账户仍须填写名称；结构化账户既没有别名也没有可用详情时不能保存。
- 账户名称在同一用户下唯一（包括已归档账户）。派生名称与已有账户冲突时不会自动编号，须填写自定义名称进行区分。账户可修改类型、重命名或归档，但不物理删除历史引用；界面统一显示为“账户类型 · 账户名称”，两者同名时只显示一次。
- 新增债务、追加借入/借出以及登记还款都必须显式选择一个可用账户，不自动使用默认账户。借入本金与追加借入记录收款账户，借出本金与追加借出记录付款账户；借入债务的还款记录付款账户，借出债务的还款记录收款账户。
- 撤销还款是原还款的补偿记录，自动继承原还款账户，不允许另选账户。编辑历史记录时可保留“历史未指定”或原已归档账户；切换账户时只能选择当前可用账户。账户归档后不能用于新的资金变动，但既有往来仍保留账户名称。
- v1/v2 历史记录中的“付款账户：…”或“收款账户：…”会在 v3 迁移时按原文字段精确回填；没有可靠来源或明确写为“无”的旧记录保持“历史未指定”，不会伪造账户。v4 会为账户增加非空固定类型，并按明确名称前缀识别微信、支付宝、现金和数字人民币；无法可靠判断的账户归为“其他账户”，不会武断推断成银行卡。v5 增加上述可选详情列，旧账户的详情保持为空，既有名称、备注、类型和历史关联不变；类型切换会清空新类型不适用的详情，避免跨类型泄漏。v6 增加 `custom` / `derived` 名称来源标记，旧账户统一保持为 `custom` 且名称不变。v7 为银行卡增加可选 `card_number`，旧账户卡号保持为空，其余字段和历史关联不变。

```bash
scripts/verify-ledger-account-migration.sh var/preview.db
```

## Turso 远程 smoke

仅在提供真实测试库凭证时执行；该测试会连接远程库并应用项目迁移：

```bash
TURSO_DATABASE_URL=libsql://... \
TURSO_AUTH_TOKEN=... \
cargo test -p zhiyu-api --test remote_turso -- --ignored --nocapture
```

未配置凭证时，该测试保持 `ignored`，本地 SQLite 结果不代表 Turso 远程验收。

生产环境必须接入真实 `EmailSender`；当前 `dev-file` 邮件驱动会主动阻止生产启动。
