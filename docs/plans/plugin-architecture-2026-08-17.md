# 知余插件式架构：根、内置插件、外部插件（最终方案，2026-08-17）

- 状态：**最终方案**。v2 → council（`council-20260817-112947`，4/4）修正为 v3 → ChatGPT Pro（https://chatgpt.com/c/6a82f28b-8810-83e8-9990-d8456216dc25 ）补充修订 → 本版。
- 类比：Obsidian。核心 = 笔记库 + 编辑器（关不掉）；内置插件 = 官方插件（可关）；社区插件 = 商店（**暂不做，进 TODO**）。
- 取代早前 `docs/module-architecture.md` 的模块化设想（建立在 local-first 之上，已随 ADR-0001 失效）。

## 一、一句话

**核心只保留「账本事实」和「长期有效的算账规则」；其余全是可关闭的插件。权威数据仍只有服务器账本一份，插件架构不引入第二套数据源。**

## 二、三层

```
┌──────────────────────── 外部插件（商店）──────────────────── TODO，暂不做
│
├──────────────────────── 内置插件（可关，关了数据不删）─────────
│   债务    账单导入（微信/支付宝/招行/民生 … 是它下面的「来源」）    自动分类规则
│   （将来：预算、周期账单、报表导出、基金/投资、提醒 …）
│
├──────────────────────── 根功能（关不掉，就是「记账」本身）────
│   账户    流水    分类    查看账本（当前官方视图：列表 / 日历 / 统计面板）
│
└──────────────────────── 内核（用户看不见的地基）───────────────
    登录/密钥    备份（覆盖插件数据）    设置    插件机制（注册、开关、扩展点）
```

- 「日历」「统计面板」不是独立能力，是「查看账本」这一根能力下的官方视图；关不关都不改变账。
- 除核心外**一律是插件**：债务（很多人不记借贷）、账单导入（手工记账的人不需要）、自动分类规则（分类目录是根，「自动帮你归类」是可选便利）。

### 判定标准（四问）
1. 没有它还能不能叫「记账软件」？不能 → 根。
2. 关掉它，别的功能会不会坏？会 → 根。
3. 它是不是「某一类人才需要」？是 → 插件。
4. **关掉它，账目数字（余额、收支、转账）会不会变？** 会 → 它留在账上的「算账语义」必须写进核心数据；功能本身仍可以是插件。

## 三、三种标记，严格分开

这是整个架构的关键概念，所有扩展点都建立在它上面：

| 标记 | 回答的问题 | 谁定义 | 谁赋值 | 例子 |
|---|---|---|---|---|
| **来源** | 这笔流水最初从哪来 | 核心 | 创建者 | 手工 / 导入插件 / 债务插件 |
| **关联** | 这笔流水和什么有关 | 核心（通用关联表） | 插件 | 这笔是某债务的还款；这笔来自某账单批次 |
| **算账语义** | 这笔怎么算账 | **核心定义有限几种** | 插件只能选，不能发明 | 收入 / 支出 / 转账 / 不算收支 |

- 「转账」已经是核心语义（流水有转账类型和来源/去向账户）；导入插件可以**识别**出一笔是转账，但一旦确认，转账身份属于核心账本事实，关掉导入插件后仍成立。
- 单笔的语义写在流水上；多笔之间的关系（还款对应哪笔借款）由核心的关联表表达。

## 四、统计面板（「查看账本」的官方视图之一）

- **形态定为多页固定列网格**（如 12 列）：组件占几格、可拖动、可调大小、可多页（「月度」「年度」「债务总览」…）。**无限画布（平移/缩放/自由坐标）移出路线图**——council 4/4 与 ChatGPT Pro 一致：方案里写的就是「按格子、占几格」，那就是网格；无限平面对「看账」没有产品收益，对单人开发者是数月交互债。除非将来出现明确需求再重新立项。
- **面板本身、网格布局、基础组件属于核心**；**插件可以贡献自己的组件**（债务：谁欠我多少；导入：本月导入多少笔）。
- 一个组件 = 唯一 ID + 占几格 + 数据从哪来 + 可选配置面板。
- 数据从哪来：**核心提供少量带语义的通用汇总**（按时间 / 分类 / 账户聚合，自动排除「不算收支」），基础组件和大多数插件组件直接用；插件自己的对象（债务余额、导入批次）走插件自己的接口。**禁止组件为了画图直接扫全部流水。**
- 布局是用户数据，核心保存；插件关掉时它的组件显示「插件已关闭」占位，布局不丢。
- 网格面板是**独立的产品步骤**，不作为插件架构的验收条件；先让现有统计页改吃通用语义（债务一拆统计立刻正确），面板随后做。

## 五、插件能做什么（扩展点）

**第一版 6 个**（债务、导入、自动分类三个内置插件全都用得上）：

| 扩展点 | 一句话 | 谁会用 |
|---|---|---|
| 页面与导航 | 在侧栏加自己的入口和页面 | 债务、导入 |
| 流水关联 | 在一笔流水上贴「这是 xx」的关联，流水页显示为可点的小标签 | 债务（这笔是还款）、导入（来自某账单） |
| 算账语义赋值 | 给流水选一种核心定义的语义（如「不算收支」） | 债务（还款、借出不是收支） |
| 流水生命周期 | 写入阶段：向核心提交**有限建议**（如分类建议），核心决定是否采纳；完成后：核心广播「流水变了」，插件各自响应 | 自动分类（建议）；债务解绑、去重（响应） |
| 插件私有数据 | 自己前缀的表，自己升级；核心不解释，其他插件不得依赖 | 全部 |
| 设置页 | 在设置里有自己一节 | 导入（账户映射）、自动分类（规则） |

**第二批**（对应功能真出现时再开）：面板组件（随网格面板一起做）、后台任务、MCP 工具（随 MCP 底座一起做）。

**明确不提供**：改核心表结构；给流水加任意自定义字段（只有上表三种核心标记）；插件任意拦截改写流水（金额、账户、时间、算账语义不许被钩子改）；**插件依赖插件**（只接收核心的「事实变化」，不假设别的插件已处理、不假设执行顺序）；插件直接读写对方的表。

## 六、铁律

1. **核心认识插件机制、稳定 ID、启停状态和扩展点，但永远不认识「债务 / 导入 / 预算」这些具体业务含义。** 核心代码里不许出现「如果是债务」。
2. **凡影响现金账户余额的事，必须是一笔流水。** 账户余额 = 流水之和，仅此而已。**核心是流水的唯一写入者**；插件想动余额就请求核心创建流水并挂关联。**估值型资产豁免**：基金/投资的买入、卖出、分红、手续费是流水，市值涨跌是插件自己的数，只出现在插件卡片上，不写回账户余额；「谁欠我多少」同理。
3. **影响余额、收支、转账等核心结果的算账语义归核心所有，写在核心数据上；关掉插件仍然生效。** 关掉债务后旧还款仍「不算收支」，只是不能再改。开关改的是界面，不是历史含义。
4. **插件关掉不删数据、不删表；重开先自检。** 关掉期间核心不替它监听流水；插件数据允许暂时陈旧，核心账本不允许失配；自检失败只影响该插件。
5. **插件故障不得阻断根功能。** 任何插件关闭、自检失败、数据损坏，账户、流水、分类、核心视图都必须照常可用。
6. **核心删除不依赖插件在线。** 用户删一笔债务插件创建的还款流水：核心提示来源、立即解除关联；插件重开后自己修。
7. **备份/恢复覆盖整个权威账本**，包括已关闭插件的数据、插件配置、关联和面板布局。
8. **插件只需一个永久稳定 ID。** 版本号、扩展点声明、权限——真做商店时再补，现在一律不预留。

## 七、现状对照：需要拆的四处耦合

| 位置 | 现状 | 改法 |
|---|---|---|
| 流水列表（`transactions.rs:29`） | SQL 直接 join 三张债务表算「这笔关联哪个债务」 | 换成核心通用「关联表」，债务插件往里写；列表只显示关联标签 |
| 统计（`transactions.rs:379,403`） | SQL 里写死「排除债务相关流水」 | 换成核心「算账语义」，债务插件把自己的流水标成「不算收支」 |
| 余额（`0016` 的 `ledger_account_movements` 视图） | 把「动过现金（`origin_kind=cash_movement`）但还没挂流水」的债务本金也算进余额；只记人情的债本来就不进 | 动过账户的钱一律补成等价流水，视图只看流水；只记人情的债继续无流水、不进余额 |
| 核心引用插件目录（`transactions.rs:14-17,26`） | 核心引用 `imports::normalize_counterparty` 和长在 `debts.rs` 里的幂等/校验工具 | 通用工具上移到核心通用层；核心不再 `use` 任何插件目录 |

导入、去重、转账识别、自动分类在代码上已是独立目录，但它们**会创建或改写流水**，接入时要走核心的写入路径（提交请求/建议，核心落库），不是贴个名字。

## 十、落地顺序（不重写，边拆边对账）
1. 写下 §六铁律 + §五扩展点 + §三三种标记，作为后续所有改动的验收标准。
2. 插件注册表：后端一张列表、前端一张列表，各插件用 ID 登记页面/表/扩展点——**半天的小检查点，不作里程碑**。
3. **债务迁数（独立一步）**：存量「动过现金但未挂流水」的本金补成等价流水（期初借出/借入）。**迁移前后现金账户余额必须一致；变了就是迁移出错，停下来查，不用「迁移说明」解释。**
4. **债务成为第一个内置插件，三处耦合分三步拆，每步对账**：余额视图只看流水 → 列表上的债务标签换通用关联 → 「排除债务」换核心语义。验收：拆完后余额和统计一个数不变。
5. 通用工具上移到核心；**导入**（含去重、转账识别）成为第二个插件，通过核心写入路径创建流水，转账身份落为核心事实；**自动分类**第三个，走「流水生命周期」提交分类建议，结果可追溯、可撤销。
6. 现有统计页改吃通用语义；再做网格面板 + 核心基础组件 + 债务的第一个插件组件。
7. 设置里加「插件」页：开/关，关了页面隐藏、数据保留、重开自检。
