## 一句话

**知余只有一份账本程序；它可以住在你的电脑里，也可以住在你的服务器上。用户选的是「账本住哪」，不是「用哪套知余」。**

## 部件

```
        桌面窗口（本地用户）      浏览器（服务器用户）      AI 工具（MCP）
                 │                      │                      │
                 └──────────────┬───────┴──────────────────────┘
                                ▼
                     账本程序（永远同一份）
                     ├ 记账界面
                     ├ 对外接口（给 MCP / 外部工具）
                     └ 账本文件 ← 唯一可写的真相
                                │
                    ┌───────────┴───────────┐
                本机文件夹                云主机磁盘
               （本地用户）              （服务器用户）
                                │
                                ▼
                     备份 = 从当前这个家复制出去的死副本，不是第二本活账
```

四个部件：账本程序、账本文件、开门的窗口、备份副本。MCP 不是第五套系统，是插在「对外接口」上的一根插头。

## 两类用户

| | 本地用户 | 服务器用户 |
|---|---|---|
| 步骤 | 下载 → 打开 → 记账（3 步） | 起一个 Docker → 建第一个主人账号（不靠邮件）→ 浏览器打开 → 生成 API 密钥接 MCP、开备份（4 步） |
| 登录 | 不需要，打开就是主人 | 需要（邮箱+密码；邮件验证变可选） |
| 数据 | 本机一个文件 | 服务器磁盘 + 异地备份 |
| 备份 | 导出一份完整账本文件，拷走即可 | 定时自动备份到别处 |
| MCP | 打开期间也能用（可选） | 常开可用 |
| 服务器多出来的唯一一件事 | — | **电脑关上，账本仍在** |

## 与「两种方案」思路的差异

- 对的一半：用户确实分「不想部署」和「要随时可连、要 AI 接入」两类。
- 错的一半：把 MCP、备份说成「只有服务器才有」。它们是程序的能力，不是住址。
- 因此不是「本地版架构 + 服务器版架构」两套，而是**同一套代码、两种包装**：桌面应用把账本程序带在身上、打开时悄悄跑起来；Docker 直接跑它。前端、接口、数据库结构只有一份，发布成本不翻倍。

## 铁律

- **永远只有一份可写账本。** 两个家之间可以搬家（整本搬走、旧家变只读），不能双开、不做同步。
- 判断一个功能放哪：记账能力属于「知余核心」；远程访问、常开 MCP、异地备份属于「部署后获得的能力」。

## 需要作者拍板

1. 本地版不要登录（打开即主人）——建议：是。
2. 桌面应用要不要**同时**保留「连接到我的服务器」——council 保留、ChatGPT 建议桌面只管本地、服务器用户用浏览器。建议：保留（现有壳已经能用，作者本人就是这样用的），但不作为开源用户的主路径。
3. 搬家只做单向（本机 → 服务器，或反向），旧家只读——建议：是，且可以晚做。

## 落地顺序

1. 服务器版：没邮件也能建第一个主人账号（现有自部署卡在这里）。
2. 本地模式：账本程序加「本机运行」方式，免登录。
3. 桌面应用内嵌账本程序，双击即用；自己走一遍「下载到记账」。
4. 备份做成完整账本文件：可导出、可按这份文件恢复；服务器版定时自动做。
5. 单向搬家。
6. MCP 插头（先服务器，本地可选开）。
7. 两页 README：本地一页、服务器一页。
